# VANTAGE — Implementation Design

**One document, not two.** The build order is on top, the design rows at the bottom. Part 8a
holds the orchestrator (`C1`); part 8b the live measurement writer, the inspector and the
supervisor (`C2`); part 8c adds `WP-19` to `WP-28` and `IMP-0125` to `IMP-0217` after these.

**Package numbers are ids, not positions.** The order is the order of the list below. **A
package row says only what it alone knows** — the box, the headline, and why it sits where it
does. What it lands is the `WP` column of the design rows, one place.

**A path below is a promise** — the code goes at that path under that name. Paths are relative
to `modules/vantage` and follow `VANTAGE_Architecture.md` §11 (cited as `ARCH §n`); where §11
names no file, the row names it and says so. Every new file carries the file header block
(`R-STYLE-1`, `COMPONENT: VANTAGE`, `R-NAME-6`).

**Rows the contract already holds are cited, never repeated.** The orchestrator's control
writing is `RCT:IMP-0032` (`src/simcore/orchestrator/control.cpp` `ControlWriter::Write`) and
the runner's input selection is `RCT:IMP-0033` (`src/simcore/runner/select_inputs.cpp`
`SelectInputs`), both in `RCT:WP-08` (`RCT_Implementation_Design.md`). The engine's recording
writer and reader are `RCT:IMP-0048` (`RCT:WP-13`). **`C2` lands the live measurement rows the
contract holds the same way:** the writer's `open`, `step`, bulk ports and oversize handling are
`RCT:IMP-0034` to `RCT:IMP-0037` (`RCT:WP-09`, landed by `WP-14`), and the inspector's attach and
read are `RCT:IMP-0038` and `RCT:IMP-0039` (`RCT:WP-10`, landed by `WP-16`). The rows below build
around them.

## Progress (`R-REQ-6a`)

**The design rows' boxes are the only hand-maintained progress state in this set.** A
package's box is recomputed from the rows it lands and the checker fails on disagreement
(`C-WPROLL`).

| Box | Means |
|---|---|
| `[ ]` | not started |
| `[~]` | started — **and the row must say `closed by <command or condition>`** |
| `[x]` | done — the tests the requirements name pass |

**Progress is not verification** (`R-REQ-6`): a ticked box says the work was done; whether the
requirement is *met* is a Test Execution Record's answer.

## Blocked, and by what

**`WP-05` needs `RCT:WP-08`.** `RunStage` hands a component the message `ControlWriter::Write`
builds and the samples `SelectInputs` picks; both are contract rows built in the same pass.

**`WP-09`'s tests need `RCT:WP-13` and the lab.** They read the engine-run recording, which the
engine's writer makes (`RCT:IMP-0048`), and they run the lab cases of
`VANTAGE_Lab_Design.md` §6, including those of `LAB-WP-10` (`coprime_periods`, `renumber_lib`,
`repeat_trigger`) and of `LAB-WP-11` (`counter_wrap`). A test whose lab output is missing skips with a printed reason
(`R-TEST-3`).

**`WP-15` needs `WP-14` and `RCT:WP-02`.** The engine hands the writer plain structs and builds the
description from `MeasDescription`, which `interfaces` defines.

**`WP-17` needs `WP-14` and `WP-15`.** The seal is the writer library's, and the supervisor seals
what the worker's writer left. It unblocks `LAB-53` (`VANTAGE_Lab_Design.md`), the lab's
`supervise.py`.

**`WP-18`'s tests need `RCT:WP-02`, `RCT:WP-03`, the lab, and `LAB-53`.** They run the lab cases of
`VANTAGE_Lab_Design.md` §6, including the `camera` topology (`LAB-WP-08`) and the `hang` and
`crash` cases, and the supervised run of `lab_tools.supervise`. A test whose lab output is missing
skips with a printed reason (`R-TEST-3`).

**`WP-20` lands `IMP-0112`.** `IMP-0112` stays `WP-17`'s row; `WP-20` is the package whose rows make it true, and its
box is ticked with them. `WP-17` stays `[~]` until then.

**`WP-23` and `WP-25` wait on three owner answers.** `IMP-0154` holds for either answer to open question 2 (it checks the hash);
`IMP-0186` waits on open question 3 (where the grace lives); the recommendations are in `VANTAGE_System_Requirements.md` §21.

**`WP-24` needs the supervisor.** It reads `<setup>.attempts.jsonl` and starts `--supervise`; both exist since `WP-17`.

**`WP-28` is last.** It deletes a path only when no file under `src`, `tests` or `scripts` imports it; `IMP-0216` finds that.

## Order, and why

The run setup first, because every other part is built from it. Then the sample buffers and the
header read at their door, because the orchestrator decides from headers and the runner selects
from buffers. Then the graph, which every step needs for its ranks. Then the events, steps,
readiness and jump of the orchestrator; then the runner that drives them through one step loop.
Equal outputs and the first divergence come once a step produces outputs; threads come last,
after one thread is right and measured (`ARCH §8`, order of work). The source checks follow the
code they scan, and the test group closes gate **G3** (`VANTAGE_DEV_PLAN.md` §5).

Part 8c, in the order a suite stays green. The scenario script first, because it is new and nothing depends on it. Then the one place
that starts the engine, so the launcher, the batch and the window all start it the same way. The launcher before its window, which
only calls it; configuration and diagnostics beside them; the batch on the supervisor; determinism after the batch, whose runs it
compares. Delivery after the parts it ships, and the retirement of the Python run path last, file by file.

- [x] **WP-01** — Run setup loader · Every other part is built from the `RunSpec` it returns; Vantage's own setup writer changes with it, so every commit on `c1` builds and passes the unit suite.
